# @atelier/design-tokens

Канонические токены дизайн-системы **Film Noir** — единственное место в репозитории, где заданы значения палитры, шрифтовых стеков, шкалы кеглей, отступов, радиусов, теней, анимации и гостевой атмосферы «Арома Ателье».

Правило простое: **значение меняется здесь и только здесь**. Приложения и дизайн-система получают его копию, а не заводят свою.

## Состав

| Файл | Что задаёт |
|---|---|
| `colors.css` | Поверхности, текст, единственный акцент-оксблад, бордеры, семантика, chart-серии, shadcn-алиасы |
| `fonts.css` | Шрифтовые стеки обеих поверхностей. Только стеки — загрузку начертаний делает потребитель |
| `typography.css` | Шкала кеглей консоли и гостя, caps-eyebrow, интерлиньяж, табличные цифры |
| `spacing.css` | База 4px |
| `radius.css` | Два регистра радиусов: плотный для консоли, щедрый для гостя |
| `elevation.css` | Тени и hairline-бордеры |
| `motion.css` | Длительности и кривые, включая `aroma-ember` |
| `profile-colors.css` | Двенадцать цветов вкусовых профилей и ramp состава микса — **слой данных, не бренд** |
| `guest-surface.css` | Атмосфера гостевого экрана: гало, карточки, CTA, сегменты, рейтинг |
| `index.css` | Точка входа, импортирует всё перечисленное |

Reset'а, утилитарных классов и `@font-face` здесь нет — только определения переменных.

## Как потребляют приложения

Прямой `@import` из `packages/` приложениям недоступен: docker build context у каждого приложения — его собственный каталог (`docker-compose.yml`, `docker-compose.prod.yml`), а npm workspaces в репозитории нет. Поэтому канон раскладывается по приложениям генератором:

```bash
node packages/design-tokens/sync.mjs
```

Скрипт собирает `index.css` в один файл и пишет его в `apps/aroma-web/src/design-tokens.generated.css` и `apps/master-web/src/design-tokens.generated.css`. Сгенерированные файлы **коммитятся** — так они попадают в docker-контекст приложения без изменения сборки. Каждое приложение импортирует свой файл первым, до собственного `:root`.

Проверка дрейфа — в CI (`atelier-design-tokens`) и локально:

```bash
node packages/design-tokens/sync.mjs --check
```

Правка `design-tokens.generated.css` руками уронит эту проверку. Это и есть смысл: значение правится в пакете.

## Как потребляет дизайн-система

`.claude/skills/aroma-atelier-design/tokens/*.css` — тонкие реэкспорты, импортирующие файлы отсюда. Собственных значений скилл не держит; исключение — `tokens/base.css` (reset и две утилиты для статических прототипов) и загрузка шрифтов с CDN в `tokens/fonts.css`: прототипы открываются как обычные HTML-страницы, `@fontsource` им недоступен.

## Границы

- **Один акцент** (PRD §12): оксблад `#B04A3E`. Второй фирменный цвет в пакет не добавляется.
- `--profile-*` и `--composition-*` — слой данных: точки профилей, signature-полосы, глифы, состав микса. Как UI-акцент не использовать.
- Monospace в системе нет: роль служебного текста держит `--font-meta` (тот же IBM Plex Sans, weight 500, широкий трекинг, `tabular-nums`). `--font-mono` оставлен алиасом, чтобы старый код не ломался.
- Ассеты бренда (знак «Дым», локап, фавикон) живут в `.claude/skills/aroma-atelier-design/assets/`: приложениям они нужны статическими файлами в `public/`, а не через CSS.

Полное описание системы — `readme.md` дизайн-системы (`.claude/skills/aroma-atelier-design/`), палитра в продуктовом контексте — `PRD.md` §12.
