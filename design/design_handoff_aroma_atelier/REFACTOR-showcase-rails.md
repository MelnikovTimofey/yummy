# Refactor: Витрина → тихие рейлы

**Scope:** заменить экран Витрины `ShowcaseTabs` (свитчер категорий) на
`ShowcaseRails` (горизонтальные тихие рейлы). Один экран,
`view === 'showcase'`. Остальные экраны не трогаем.

> Это **точечный рефактор** поверх основного хэндоффа (`README.md`).
> Токены, atoms, маршрутизация, API — оттуда. Здесь только дельта.

---

## Зачем

Текущая Витрина — **свитчер категорий**: горизонтальный ряд табов
(serif-заголовок + caps-тип рейла) под topbar, активный таб подчёркнут
`border-bottom 2px --primary`, ниже — вертикальный список миксов
**только выбранной** категории.

**Проблема:** табы заставляют гостя выбирать раздел и прячут остальные;
по сути это навигация, которой на витрине быть не должно. PRD-инвариант —
«листай и смотри», без модальной фильтрации.

**Новое решение — тихие рейлы:** все категории видны одновременно как
вертикальный стек секций. Каждая секция = serif-заголовок + meta-pill
типа рейла + **горизонтально скроллящийся** ряд компактных карточек.
Никакого выбранного/невыбранного состояния, никакого свитчера. «Тихо»,
потому что меньше контролов и хром-элементов на экране.

| | Было (`ShowcaseTabs`) | Стало (`ShowcaseRails`) |
|---|---|---|
| Категории | один таб активен | все видны сразу |
| Навигация | tab switcher | вертикальный скролл секций |
| Карточки | вертикальный список | горизонтальный скролл, `width: 196` |
| Состояние | `active: railId` | **нет состояния** |
| Хвост рейла | — | dashed-пилюля «Все» → `view === 'rail'` |

---

## Что удалить

В блоке `view === 'showcase'`:

1. **Category switcher целиком** — `<div>` с
   `display:flex; gap:14; overflow-x:auto` и кнопками-табами
   (`borderBottom 2px solid primary`).
2. **State `active`** (`useState<railId>`) и `onChange` хэндлер таба.
3. Логику «показывать миксы только выбранного рейла»
   (`rails.find(r => r.id === active)`).

Старая Витрина была **stateful**. Новая — **stateless**: просто маппинг
всех рейлов. Это упрощает компонент.

## Целевая разметка

Референс-исходник: `aroma/showcase.jsx` → именованный экспорт
**`ShowcaseRails`** (третий вариант, `Variant C` в файле). Воссоздать
один-в-один в кодовой базе на существующих atoms.

### Структура секции (рейла)

```
<PhoneBody> gap 22, padding 16px 0 20px      // вертикальный стек
  └ <section> gap 10                          // один рейл
     ├ header (padding 0 20px)                // отступы только у шапки
     │   ├ <h2 font-display 21>  rail.title
     │   └ meta-pill (caps)      rail.kind
     └ rail-scroller                          // horizontal scroll
         display:flex; gap:10; overflow-x:auto; padding:0 20px 4px
         ├ <article> × N   (карточка микса, width 196)
         └ <button> «Все»  (dashed, width 64)
```

**Важно:** padding по горизонтали (`20px`) живёт на **шапке** и на
**скроллере**, а не на `<section>` — иначе горизонтальный скролл
обрежется отступом и карточки не доедут до края. `PhoneBody` здесь идёт
с `padding: '16px 0 20px'` (нулевой по бокам).

### Карточка микса (`width: 196`, `flex: 0 0 auto`)

```
<article>  radius 16, padding 12, gap 10
   background:
     radial-gradient(circle at 86% 0%, profileColor[m.profiles[0]]48 0%, transparent 60%),
     linear-gradient(180deg, rgba(40,17,17,0.96) 0%, rgba(22,11,12,0.96) 100%)
   border: 1px solid var(--line)
   box-shadow: inset 0 1px 0 rgba(255,244,236,0.04), 0 14px 24px rgba(0,0,0,0.22)

   ├ row: ProfileGlyph 44  +  RatingPill (margin-left:auto)
   ├ <h3 font-display 15.5>  m.name        // min-height 2.2em — чтобы карты выровнялись
   ├ SignatureBar height 3
   └ <p font 11, line-height 1.25>  m.flavors.join(' · ')
        2-line clamp: -webkit-line-clamp:2; -webkit-box-orient:vertical; display:-webkit-box; overflow:hidden
```

Описаний-абзацев у миксов на витрине **нет** — только `flavors`,
обрезанные до 2 строк. Это ключ к «тихости»: карточка несёт имя +
сигнатуру + ноты, и всё.

### Хвостовая пилюля «Все»

```
<button>  width 64, flex 0 0 auto
   border: 1px dashed var(--line)
   background: rgba(20,10,10,0.5)
   caps 11px, центр, color --text-1
   текст: «Все»
```

→ открывает `view === 'rail'` для этого рейла (раскрытый рельс,
`RailView` из `extras.jsx`). Передавать `railId`/`railType`, чтобы
`RailView` знал, что грузить.

## Meta-pill типа рейла

Caps-метка в шапке (`rail.kind`) — не плоский текст, а пилюля:

```css
padding: 3px 8px;
border-radius: 999px;
background: rgba(81,33,21,0.5);
border: 1px solid var(--line-soft);
color: var(--text-1);
/* + .aroma-caps: 10.5px, letter-spacing .18em, uppercase */
```

Маппинг `rail.type → kind` — **тот же, что в README §6**, не меняется:

| `rail.type` | подпись |
|---|---|
| `statistical` | Выбор гостей |
| `prepared` | Редакция |
| `curated` | Мастера |

## Данные и API

Без изменений относительно `ShowcaseTabs`:

- Источник — `GET /guest/home/rails` (тот же эндпоинт).
- Маппинг ответа: `rails[].title`, `rails[].type → kind`, `rails[].mixes[]`.
- Только `available === true` (PRD-инвариант) — фильтровать миксы внутри
  каждого рейла, как и раньше.
- Карточка читает: `m.name`, `m.profiles`, `m.flavors`, `m.rating`.

Раньше один экран рендерил миксы **одного** рейла; теперь — **всех**
рейлов сразу. Если `rails[].mixes` уже приходит в ответе `/home/rails`,
дополнительных запросов не нужно. Если миксы догружались лениво по
выбору таба — **снять ленивую загрузку**, грузить все рейлы разом
(их 3, по 3-6 карточек — дёшево).

## Поведение

- **Тап по карточке** → открыть `MixCardHero` (bottom-sheet), как из
  любого другого списка миксов. Поведение идентично каталогу/подбору.
- **Тап по «Все»** → `view === 'rail'` с контекстом этого рейла.
- **Горизонтальный скролл** рейла — нативный (`overflow-x: auto`),
  scrollbar скрыт (`.aroma` уже прячет скроллбары глобально).
- **Вертикальный скролл** страницы — между рейлами.
- Никаких tab-кликов, никакого активного состояния — экран stateless.

## Токены

**Новых нет.** Всё из README §`Design tokens`: `--line`, `--line-soft`,
`--text-1`, `profileColor[...]`, card-gradient, caps-стиль. Если atoms
(`ProfileGlyph`, `SignatureBar`, `RatingPill`, `PhoneBody`, `Topbar`,
`SegmentNav`) уже вынесены по основному хэндоффу — переиспользовать,
не дублировать.

Topbar + 3-tab `SegmentNav` (Подбор / Витрина / Каталог, активна
«Витрина») остаются без изменений — это навигация уровня приложения, а
не свитчер витрины.
