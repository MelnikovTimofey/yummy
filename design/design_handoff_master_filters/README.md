# Handoff: единые фильтры Мастера (#464)

Мокап сделан по скиллу `atelier-feature-design`. Владелец выбрал канон дизайн-системы
(`FilterChip`, `MasterSortPill`, «Фильтры» с ползунками) вместо паттернов «Каталога» или «Полки».

Статус: **ждёт согласования владельцем.**

## Как открыть

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Затем откройте `http://localhost:8765/design/design_handoff_master_filters/mockups.html`.
`mockups.html#shot=<id>` показывает один экран. Снимки лежат в `screens/<id>.png`.

| id | экран |
|---|---|
| `shelf` | «Полка» по умолчанию |
| `shelf-brand` | открыт список «Бренд» |
| `shelf-active` | выбраны фильтры, «Сбросить» |
| `catalog` | «Каталог» |
| `mixes` | «Миксы» |
| `access` | «Доступ», операторы |
| `empty` | ничего не найдено |
| `phone`, `phone-sheet` | телефон 375 px и шторка «Фильтры» |

## Что реализовать

Одна панель на всех экранах со списками.

**Первая строка: поиск и статусы.**
- Поиск: один компонент, `type="search"`, иконка `search`.
- Статусы: `FilterChip` с числом. У «Все» числа нет. Ноль приглушён, но показан. В «Доступе» чисел нет вообще.

**Вторая строка: атрибуты, «Сбросить», сортировка.**
- Атрибуты: `FilterChip` с шевроном, без чисел. По клику открывается список с галочками и поиском, выбор применяется сразу, внизу «Выбрано N» и «Очистить».
  - Одно значение — его название на чипе, несколько — «Бренд: 2».
  - Атрибуты с одним выбором («Миксы», «Рейлы») — тот же список с одним выбором.
- «Сбросить» — в конце строки, если выбран хоть один фильтр. Поиск не трогает.
- Сортировка `MasterSortPill` «По …» — справа.

**Пустой результат:** «Уберите один из фильтров.» и «Сбросить фильтры». Эта кнопка снимает и поиск.

**Телефон:**
- Поиск и кнопка «Фильтры» с ползунками и числом выбранных атрибутов.
- Под ними — ряд статусов с прокруткой, в том же порядке и с теми же подписями, что на десктопе.
- Шторка: «Сортировка» и атрибуты чипами (у длинных групп — «Ещё N»), внизу «Сбросить» и «Показать N».
- Так выглядят «Полка», «Каталог» и «Миксы».

| экран | статусы | атрибуты | сортировка |
|---|---|---|---|
| Полка | Есть, Заканчивается, Проверьте остаток, Закончились, Стоп, В плане, Мало данных | Бренд, Характер, Крепость, Миксы | По сроку, По расходу, По остатку, По названию, По приходу |
| Каталог | В наличии, Нет наличия, Архив | Категории, Бренд, Вкусы, Мета-теги | По названию и др. (как колонки) |
| Миксы | Виден гостю, Скрыт, Блокирован | Профиль, Рейлы, Бренды, Вкусы, Мета-теги | По спросу и др. (как колонки) |
| Доступ | Активны, Ждут привязки, Выключены | нет | нет |

Что уходит:
- `ShelfFilterPanel` (сетка чекбоксов) и нативный `<select>` сортировки «Полки»;
- `FilterMultiSelect` / `FilterSingleSelect` в раскрывашке «Ещё фильтры»;
- строки «Категории» и «Профиль»;
- класс `.chip` в «Доступе»;
- отдельный порядок чипов `SHELF_MOBILE_CHIPS`.

## Что не входит

- переключатели режимов (`.shelf-seg`: «Полка / К заказу / Закупка», «Все табаки / Идеи для закупки»);
- чипы-разделы «Закупки» — это навигация, а не фильтры;
- серверная логика фильтров и query-параметры.

## Вопросы владельцу

1. «Категории» в «Каталоге» и «Профиль» в «Миксах» сейчас стоят строкой, выбор в один клик. В мокапе они свёрнуты в чип-атрибут, как в ките. Оставить так или вернуть строку?
2. Подпись выбранного атрибута: название одного значения, «Бренд: 2» для нескольких. Подходит?
3. Сортировка в «Каталоге» и «Миксах»: пилюля «По …» и заголовки колонок с общим состоянием, или только одно из двух?
4. «Мало данных о расходе» в мокапе — статус «Мало данных 237», а «Есть / Нет в миксах» — атрибут «Миксы». Согласны?
