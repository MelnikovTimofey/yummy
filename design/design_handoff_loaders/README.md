# Handoff: лоадеры вместо текста «Загружаем…»

Мокап по скиллу `atelier-feature-design`, issue #394. Сейчас каждое ожидание гостя — строка текста на пустом экране («Собираем подбор…», «Загружаем витрину…», «Сохраняем…» на кнопке).

## Статус

**Согласован** (владелец, 2026-10-24) целиком, дымка по скелету остаётся. Вариант «скелет без дымки всегда» (`recs-static`) отвергнут: неподвижный силуэт читается как зависший экран; без движения скелет только при `prefers-reduced-motion`.

Решения владельца до мокапа (2026-10-24): сначала гость, потом Мастер; скелет там, где известна форма экрана, знак «Дым» там, где формы нет; на кнопках подпись остаётся, рядом знак.

Реализован для гостя в #396: снимки приложения на медленном API в `impl/` (`recs`, `catalog`, `showcase`, `reels`, `profiles`, `onboarding-busy`, `smoke-busy`, `gate-busy`). Мастер — #397: скелет строк в списках и таблицах, знак «Дым» в расчётах (прогноз полки, закупка, код смены), знак на занятых кнопках; снимки `impl/master-*`. Цвета знака в консоли — токены `--accent*`: lint:design запрещает литералы цвета в master-web.

## Бриф

- **Кто:** гость `aroma-web`. Мастер — второй срез на тех же приёмах, свой мокап не нужен, если владелец не попросит.
- **Края:** ответ быстрее ≈ 300 мс — лоадер не показывается, экран не мигает; ошибка — как сейчас, скелет исчезает; `prefers-reduced-motion` — без движения (`recs-static`); скринридер — скрытый текст в `role="status"`, у кнопки `aria-busy`.
- **Данные и контракт:** не меняются.
- **Нагрузка:** нет — новых запросов нет.
- **Инварианты:** allowed, ни один не затронут.
- **Вопросы к клиенту:** нет.

## Что реализовать

1. **Скелет** (`recs`, `for-you`, `showcase`, `catalog`, `cabinet`). Силуэт будущего экрана: герой, строки микса, рейлы Витрины. Всё, что известно до ответа, рисуется настоящим: шапка, вкладки, заголовок «Тоже подходят», поиск и «Фильтры», «Собрать свой микс», панель. Блоки — `rgba(232,230,224,.06)` поверх карточки, радиусы как у настоящих элементов.
2. **Дымка по скелету.** Широкая светлая полоса проходит слева направо за 1,8 с. Прозрачность и размер блоков не меняются, поэтому это не пульс, запрещённый каноном для индикаторов ожидания. При `prefers-reduced-motion` дымки нет (`recs-static`).
3. **Знак «Дым» в движении** (`onboarding`, `reels`, `harmony`). Пути знака без изменений (`assets/logo-mark-oxblood.svg`). Каждая струя прорисовывается снизу вверх и тает сверху, сдвиг между струями 0,2 с, цикл 1,8 с. По центру экрана высота 56 px; в строке 16 px, штрих толще (8 вместо 5), чтобы знак не стал волоском.
4. **Кнопки** (`buttons`). Подпись остаётся, слева знак 16 px. Кнопка не нажимается и не сереет: серый читается как «нельзя», а не «идёт». На бордовой заливке струи цвета `--cta-solid-ink`, на контуре — бордовые, у «Удалить» — `--danger`.
5. Скелет и знак — один компонент на приложение (`Skeleton`, `SmokeLoader`), строки «Загружаем…» уходят из разметки. Задержка 300 мс — в компоненте, а не на каждом экране.

## Чего не делать

- Пульс прозрачности или масштаба, вращающийся спиннер, прогресс-бар.
- Текст под знаком («Загружаем…»): он остаётся только для скринридера.
- Отдельную заставку при запуске, правки ошибок и пустых состояний.

## Как открыть

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Сервер из корня репо, адрес `http://localhost:8765/design/design_handoff_loaders/mockups.html`. Дымка и струи анимированы.

- `mockups.html#shot=<id>` — один телефон 375×780: `now`, `recs`, `for-you`, `showcase`, `catalog`, `cabinet`, `onboarding`, `reels`, `harmony`, `buttons`, `recs-static`.
- `screens/` — снимки Playwright, `screens/overview.png` — вся доска.

## Файлы

- `mockups.html` — статичная доска без React: оболочка и панель из `../design_handoff_for_you_mood_entry/mockups.html`, свои классы `.sk*` (скелет) и `.smoke*` (знак).
