# Handoff: «рилсы» миксов (#153)

Мокап сделан по скиллу `atelier-feature-design`. Гость листает миксы полноэкранной вертикальной лентой. Фон каждого рилса — сцена, сгенерированная по вкусам микса: мятный дышит холодом, цветочный раскрывается лепестками. Бриф, решения владельца и ответы клиента — в [issue #153](https://github.com/MelnikovTimofey/yummy/issues/153).

## Как открыть

`board.jsx` подгружается по XHR, поэтому нужен статический сервер из корня репо:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Затем открыть `http://localhost:8765/design/design_handoff_reels/mockups.html`.

- Доска — кликабельный прототип. Лента листается колесом, тачпадом или свайпом внутри телефона. Тап по сцене ставит паузу. «Подробнее» открывает карточку, «Покурить» — «Покажите мастеру», «×» — назад к Подбору. Переключатель «Стиль сцен» в шапке доски меняет A/B во всех телефонах.
- `mockups.html#shot=<id>` — один телефон 375×780 без доски. `&style=B` — стиль сцен B. Доступные `id`: `entry-a`, `entry-b`, `reel-first`, `reel-bloom`, `reel-long`, `reel-norating`, `reel-paused`, `reel-sheet`, `reel-confirm`, `reel-gone`, `reel-empty`. Смена одного хэша страницу не перезагружает, поэтому для другого кадра добавьте или поменяйте query (`?n=2#shot=…`).
- `screens/` — снимки Playwright: `scenes.png`, `rule.png` (секции доски), `entry-a.png`, `entry-b.png`, `reel-first.png`, `reel-first-b.png`, `reel-long.png`, `reel-sheet.png`, `reel-gone.png`, `reel-empty.png`.

## Файлы

- `mockups.html` — оболочка. Экранные классы и классы доски скопированы из `design_handoff_guest_cabinet`, новые (`.reel*`, `.scene`, `.p`, `.m-*`) — в конце блока `<style>`.
- `board.jsx` — правило выбора сцены (`pickScene`), сцены (`Scene`), лента (`Feed`, `Reel`), вход (`EntryLink`, `EntryStrip`), карточка «Из ленты» и доска. Подбор и «Покажите мастеру» — из гостевого UI-кита без изменений.
- Данные — витрина прода на 2026-10-15 из `../design_handoff_showcase_compact/showcase-data.js`. Оценок гостей в снапшоте нет, поэтому шести миксам даны условные оценки, чтобы показать «★» (`RATED` в `board.jsx`).

## Сцены здесь — приближение

В мокапе сцены сделаны на CSS-анимациях. В приложении каждая сцена — композиция Remotion: `useCurrentFrame` + `interpolate`, шум — `random(seed)` с `seed = mix.id`. Композиции играет `@remotion/player` прямо на телефоне гостя. Видеофайлов, хранилища и рендера на сервере нет. Нужно повторить характер движения, а не CSS один в один.

## Что реализовать

1. **Режим ленты** — полноэкранный, без шапки и нижней панели, как Миксер.
   - Вертикальный свайп со снапом: один жест — один рилс. Автоперехода нет (ответ клиента).
   - Сверху «×» (Lucide `X` 22 px, `aria-label` «Закрыть ленту») — возврат туда, откуда гость пришёл. По центру счётчик `05 · из 33`, капсы 11 px.
   - Порядок: подбор гостя по онбордингу, затем остальные доступные миксы `GET /guest/catalog/mixes`, без повторов. Не прошёл онбординг — лента начинается с каталога.
2. **Рилс**:
   - фон — сцена на весь экран;
   - поверх — док с fade снизу: капсы до трёх профилей; название (Literata 30 px, до двух строк); `RatingPill` с числом оценок — только если гости оценивали (#185), иначе строки нет; вкусы через `·`; состав `CompositionStack` без полосы; кнопки «Подробнее» (ghost) и «Покурить» (`AromaCTA` с `pulse`);
   - текст — HTML-слой, не часть композиции: читается скринридером и не дёргается при паузе;
   - появление дока — 240 мс, opacity + сдвиг 6 px, ступенькой 60 мс. Сцена — бесшовный цикл ≈ 6 с.
3. **Подсказка** «Листайте вверх» с `chevron-up` — только на первом рилсе, пока гость не листнул.
4. **Пауза** — тап по сцене (кнопка на всю сцену, `aria-label` «Пауза» / «Продолжить»). В паузе по центру круг 56 px с `play`.
5. **Производительность**:
   - играет только активный рилс, соседи — статичный кадр, дальше — пустые слоты той же высоты;
   - Remotion грузится отдельным чанком при входе в ленту;
   - `prefers-reduced-motion` — статичный кадр (`<Thumbnail>`), без появления дока.
6. **«Подробнее»** — карточка микса (`MixSheet`) с надзаголовком «Из ленты» и кнопкой «К ленте». Оценка ставится как обычно.
7. **«Покурить»** — тот же `POST /guest/events/smoke-cta` и тот же экран «Покажите мастеру». «Готово» возвращает в ленту на тот же рилс. Источник выбора в аналитике не различаем (решение владельца).
8. **Микс закончился** (`reel-gone`) — `smoke-cta` ответил 404. Строка-статус над кнопками: «Этот микс сейчас недоступен по наличию. Листайте дальше — остальные на месте.», CTA неактивна, лента не перескакивает.
9. **Пустая лента** (`reel-empty`) — знак «Дым», «Сейчас показать нечего», «Ни одного микса в наличии. Мастер уже в курсе — спросите его, что будет сегодня.», «Вернуться».

## Правило выбора сцены

Профили у миксов прода раздуты (4–8 штук) и не упорядочены по силе: у «Морозной ягоды» первым идёт «Цветочно-травяной». Поэтому сцена берётся из `flavors`:

1. Каждый вкус относится к одному из шести мотивов по словарю (`MOTIFS` в `board.jsx`): **Холод**, **Цветы и травы**, **Сок**, **Ягоды**, **Тепло**, **Дым**.
2. Побеждает мотив с бо́льшим числом вкусов, при равенстве — тот, чей вкус идёт в списке раньше. **Холод перебивает всё** — самое яркое ощущение, и это пример клиента.
3. Второй по счёту мотив добавляет треть частиц своего цвета.
4. Ни один вкус не узнан — сцена по первому профилю. Профилей нет — «Дым».
5. Цвет сцены — из `PROFILE_COLORS`. «Сок» — «Цитрусовый», если есть цитрус, иначе «Фруктовый». «Тепло» — «Пряный», если пряностей не меньше половины, иначе «Десертный».

Таблица на доске (`rule.png`) считается тем же кодом, что и сцены. В приложении правило — чистая функция в `apps/aroma-web/src/lib/` с unit-тестами на примерах из таблицы. Словарь пополняется по мере появления новых вкусов в каталоге. Неузнанный вкус не ломает сцену — она падает на профиль.

## Варианты на согласование

| Вопрос | A | B |
|---|---|---|
| **Стиль сцен** | **Атмосфера** — язык `ProfileGlyph`: размытые орбы, туман, свет в цветах профиля, без предметов. Ближе к системе, мягче. | **Образ** — тонкие линейные мотивы штрихом знака «Дым»: снежинки, лепестки, дольки, ягоды, искры, струи. Мотив считывается сразу, но это уже иллюстрация. |
| **Вход в ленту** | **Ссылка над подбором** (`entry-a`): «Смотреть лентой» с `clapperboard` 16 px — тихо, как «Подобрать под настроение». Подбор не меняется. | **Полоса превью** (`entry-b`): кружки 60 px со статичным кадром сцены и названием, как Stories. Нажатие открывает ленту с этого микса. Заметнее, но сдвигает «Лучшее совпадение» вниз на ~100 px. |

Отдельная нижняя кнопка для ленты не предлагается: в панели уже пять пунктов, вместе с «Кабинетом» (#151).

## Исключение из дизайн-системы

VISUAL FOUNDATIONS запрещает иллюстрации и выразительную анимацию: «Фотографий нет вообще… Никаких паттернов, текстур, шума и иллюстраций»; bounce и параллакс не используются. Лента — сознательное исключение, только для этого режима:

- сцены — анимированный фон на весь экран;
- в стиле B — линейные мотивы.

Остальные правила действуют и в ленте: один акцент — только заливка CTA и метки, цвета профилей — слой данных, без bounce, spring и параллакса. После согласования исключение записывается в `aroma-atelier-design/readme.md` (VISUAL FOUNDATIONS → «Анимация»), а рилс добавляется в гостевой кит.

## Что не реализовывать

- Переключатели доски — только для согласования.
- Условные оценки из `RATED` — в приложении рейтинг берётся из данных.
- Экспорт MP4 для соцсетей — возможный второй этап (`@remotion/renderer` из тех же композиций), в пилот не входит.
- Звук.

## Сопутствующие правки в срезах реализации

- `apps/aroma-web/package.json` — `remotion` и `@remotion/player` (лицензия: бесплатная, частное лицо или команда до 3 человек).
- `apps/aroma-web/src/components/reels/` — композиции сцен, `Feed`, `Reel`; `src/lib/reel-scene.ts` (+ `.test.ts`) — правило выбора сцены.
- `PRD.md` — режим ленты в гостевом потоке.
- `tests/smoke/tests/aroma-smoke.spec.ts` — вход в ленту, свайп к следующему рилсу, «Покурить» из рилса → «Покажите мастеру».
- `aroma-atelier-design` — исключение в readme, рилс в гостевом ките, `clapperboard` в ICONOGRAPHY (если выбран вход A).
