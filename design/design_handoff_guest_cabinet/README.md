# Handoff: личный кабинет гостя (#151)

Мокап сделан по скиллу `atelier-feature-design`. Гость по желанию входит через Telegram и получает кабинет: историю выборов, избранное (в том числе миксы, собранные в «Намиксуй») и «Для вас» на Подборе с защитой от пузыря одного вкуса. Бриф и критерии приёмки — в [issue #151](https://github.com/MelnikovTimofey/yummy/issues/151). Правила — `PRD.md` §4, §6.5, §8.9 (PR #236).

## Как открыть

`board.jsx` подгружается по XHR, поэтому нужен статический сервер из корня репо:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Затем открыть `http://localhost:8765/design/design_handoff_guest_cabinet/mockups.html`.

- Доска — кликабельный прототип. Всё живое: нижняя панель, вкладки кабинета, карточки, сердечко, вход (экран Telegram — заглушка), выход и удаление.
- `mockups.html#shot=<id>` — один телефон 375×780 без доски, для скриншотов в issue и PR. Доступные `id`:
  - «Для вас»: `fy-a`, `fy-b`, `fy-a-varied`, `fy-cold`, `fy-mood`, `fy-mood-result`;
  - кабинет: `cab-anon`, `cab-tg`, `cab-tg-expired`, `cab-tg-error`, `cab-history`, `cab-favorites`, `cab-empty`, `cab-delete`;
  - карточка микса: `sheet-fav`, `sheet-anon`, `sheet-stock`, `sheet-custom`;
  - вернувшийся гость: `returning`, `returning-after`.
- `screens/` — снимки секций доски: `foryou.png`, `cabinet.png`, `sheet.png`, `returning.png`.

## Файлы

- `mockups.html` — оболочка. Экранные классы скопированы из гостевого UI-кита (`.claude/skills/aroma-atelier-design/ui_kits/aroma-guest/index.html`), классы доски — из `design_handoff_showcase_compact`. Новые стили (`.cab-*`, `.fy-*`, `.heart-btn`, `.tg-stub`) лежат в конце блока `<style>`.
- `board.jsx` — экраны кабинета, «Для вас», карточка микса с сердечком, знакомство с входом и доска. Подбор по онбордингу, «Покажите мастеру» и примитивы берутся из UI-кита без изменений.
- Данные — витрина прода на 2026-10-15 из `../design_handoff_showcase_compact/showcase-data.js`. История, избранное и собранные миксы гостя условные, миксы в них настоящие. «Ягодная классика» как удалённый мастером микс — условность для края.

## Что реализовать

1. **Нижняя панель на пять пунктов**: пятый — «Кабинет», Lucide `CircleUserRound` 24 px, название в `aria-label`. Остальные пункты не меняются.
2. **Кабинет без входа** (`cab-anon`):
   - знак `ProfileGlyph` 72 px, надзаголовок «Кабинет», заголовок «Запомним, что вам понравилось»;
   - три пункта: история, избранное, «Для вас» без онбординга в следующий раз;
   - строка «Без входа всё работает как прежде. Кабинет действует в этом заведении.»;
   - согласие — тот же чекбокс, что на гейте 18+: «Согласен на обработку Telegram id для истории и избранного. Политика»;
   - CTA «Войти через Telegram» неактивна, пока нет согласия. Кнопка в цветах системы, а не синяя телеграмная: акцент один;
   - Telegram не ответил или гость отменил вход → гость остаётся анонимом, ошибка под CTA: «Telegram не ответил. Попробуйте ещё раз — подбор и каталог работают и без входа.»
3. **Вход — через бота по ссылке** (#239, #266; виджет Telegram отвергнут после проверки на iPhone):
   - «Войти через Telegram» → `POST /guest/auth/telegram/start` → сайт открывает `botUrl` (`https://t.me/aroma_atelier_client_bot?start=<код>`), приложение Telegram показывает чат с ботом;
   - на сайте экран ожидания (`cab-tg`): знак, «Вход через Telegram», «Подтвердите вход в Telegram», «Мы открыли чат с ботом Арома Ателье. Нажмите там «Запустить», затем «Войти» — кабинет откроется здесь.», строка «Ждём подтверждения…» с пульсирующей точкой (`--accent`, без анимации при `prefers-reduced-motion`), «Открыть Telegram ещё раз» (ghost) и «Отмена»; нижней панели нет;
   - опрос `POST /guest/auth/telegram/status` (код и секрет опроса в теле) раз в 2 с; в скрытой вкладке опрос на паузе и сразу повторяется при возврате в браузер;
   - `ok` → токен в `localStorage`, возврат на экран, откуда пришёл, строка «Вы вошли. Вкусы из онбординга сохранены в кабинете.»;
   - `expired` (10 минут) → `cab-tg-expired`: «Ссылка устарела», «Ссылка для входа живёт 10 минут. Начнём заново?», «Войти через Telegram», «Отмена»;
   - `consent-required` (вернувшийся гость, у которого кабинета нет) → экран `cab-anon` с ошибкой под CTA «Кабинета ещё нет — отметьте согласие и войдите снова.»;
   - бот не настроен (`botUsername: null`) — пункта входа нет, «Кабинет» показывает только объяснение без кнопки;
   - блок «Только в мокапе — ответ бота» на экране ожидания — имитация, в приложение не переносится.
4. **Кабинет после входа** (`cab-history`, `cab-favorites`):
   - заголовок «Кабинет»;
   - «Ваши вкусы» — выбранные профили чипами и кнопка «Изменить вкусы», которая открывает онбординг заново;
   - `SegmentNav`: «История · N» и «Избранное · N»;
   - внизу «Выйти» и «Удалить кабинет» (`--danger`).
5. **История**:
   - каждое нажатие «Покурить», сгруппированное по датам; сегодняшние — «Сегодня»;
   - строка — `ProfileGlyph` 44 px, название (до двух строк), `SignatureBar` 3 px, справа оценка гостя «★ 5», если он её поставил;
   - собранный микс — надпись «Собран вами» над названием;
   - микс, удалённый мастером, — строка приглушена (opacity .62), не нажимается, подпись «Больше не готовим»;
   - нажатие открывает карточку микса с надзаголовком «Из истории».
6. **Избранное**:
   - те же строки;
   - если табака нет в наличии — «Сейчас нет: <бренд> <табак>»: карточка открывается, но «Покурить» неактивна, и причина названа;
   - удалённый мастером — «Больше не готовим».
7. **Сердечко в карточке микса** (`sheet-fav`):
   - Lucide `Heart` 22 px справа в шапке карточки, кнопка 40×40;
   - выключено — `--text-muted`, включено — кремовое `--text-0` с заливкой. Акцентом не красим;
   - `aria-pressed`, `aria-label` «В избранное» / «Убрать из избранного»;
   - у анонима сердечко есть, по нажатию — шторка «Избранное живёт в кабинете» с «Не сейчас» и «Войти» (`sheet-anon`).
8. **Собранный микс** (`sheet-custom`):
   - надзаголовок «Собран вами», описание с датой и вердиктом гармонии, состав и доли;
   - блока оценки нет;
   - сердечко и «Покурить» как у каталожного микса;
   - «Покурить» ведёт на «Покажите мастеру» с пометкой «Собран гостем», как в «Намиксуй».
9. **«Для вас»** — вместо подбора по онбордингу у вошедшего гостя, у которого три и больше выборов. Состав и правила — PRD §6.5. Раскладка — **A · по слотам** (`fy-a`, выбор владельца 2026-10-20):
   - подписи `.aroma-caps` по порядку: «Новое в вашем вкусе» (герой + три строки), «Шаг в сторону» (одна строка), «Снова» (одна строка, в конце);
   - заголовок «Для вас», подзаголовок «По вашим выборам, оценкам и избранному.»;
   - герой — лучший новый микс с причиной вместо описания, составом и «Покурить»;
   - у каждой строки причина одной фразой: «Черника и холодок — рядом с вашими любимыми», «Мастера часто сводят ягодное с цитрусовым», «Ваша оценка ★ 5 · выбирали 5 раз»;
   - **подсказка против пузыря** — если 4 из 5 последних выборов один микс или один ведущий профиль:
     - карточка над героем: «Давно на одном вкусе», затем факт и строка с юмором: «Четыре из пяти последних — «Морозная ягода». Мастер уважает постоянство, но рядом есть кое-что.»;
     - ниже кнопка-строка с миксом «Шаг в сторону»;
     - ничего не запрещает и не прячет любимое.
10. **«Подобрать под настроение»** (`fy-mood`, `fy-mood-result`, решение владельца 2026-10-20):
    - тихая ссылка под заголовком «Для вас» и в `fy-cold` у вошедшего гостя: капсы 11 px, `--text-0`, шеврон `chevron-right` 18 px, без рамки и заливки;
    - открывает обычный онбординг (профили → вкусы), начиная с пустого выбора. Сверху строка с «←» назад к «Для вас»: «Под настроение. Только на этот визит. Вкусы в кабинете не изменятся.»; нижней панели нет, как на онбординге;
    - выдача — подбор по онбордингу этого визита (тот же `POST /guest/onboarding/recommendations`, что у анонима). Сверху строка «Под настроение · <профили>. Подбор на этот визит. «Для вас» и вкусы в кабинете не изменились.» и ссылка «‹ Вернуться к «Для вас»»;
    - вкусы в кабинете и «Для вас» не меняются. «Покурить» отсюда пишется в историю как обычно;
    - выдача живёт до конца визита (до «Вернуться к «Для вас»» или перезагрузки), не сохраняется в кабинете.
11. **Меньше трёх выборов** (`fy-cold`): подбор по сохранённому онбордингу, как сейчас. Сверху строка «„Для вас“ соберётся, когда у нас будет больше ваших выборов. Пока — по вкусам из онбординга.» Призывать выбирать или курить чаще нельзя (CONTENT FUNDAMENTALS).
12. **Вернувшийся гость** (`returning`):
    - на знакомстве под «Пропустить знакомство» — «Уже были у нас?» и «Войти через Telegram»;
    - после входа знакомство и онбординг пропускаются, гость сразу попадает на Подбор с «Для вас».

## Варианты «Для вас»

Владелец выбрал (2026-10-20): **A · по слотам** — защита от пузыря должна быть видна гостю.

| Вариант | Решение | Как выглядит | За | Против |
|---|---|---|---|---|
| **A · по слотам** (`fy-a`) | **выбран** | Три подписи `.aroma-caps`: «Новое в вашем вкусе» (герой + три строки), «Шаг в сторону» (одна строка), «Снова» (одна строка, в конце). | Логику подбора видно глазами: гость понимает, что повтор один, а шаг в сторону — нарочно. | Длиннее: шаг в сторону уходит ниже первого экрана, если нет подсказки. |
| B · одним списком (`fy-b`) | отвергнут | Герой и «Тоже для вас» — пять строк; повтор и шаг в сторону помечены капсами внутри строки. | Компактнее, похоже на нынешний Подбор. | Правило «один повтор, один шаг в сторону» менее заметно. |

## Что не реализовывать

- Вариант B (`fy-b`) отвергнут и остаётся на доске для истории решения.
- Переключатели доски и блок «Только в мокапе — ответ бота» — только для согласования.
- Витрина, Каталог и Миксер не меняются, в мокапе это заглушки. Сердечко появляется в карточке микса, на каком бы экране её ни открыли.
- «0 выборов» под героем подбора по онбордингу — так экран из кита показывает миксы без событий. Это не новое.

## Сопутствующие правки в срезах реализации

- `apps/aroma-web/src/components/aroma/BottomNav.tsx` — пятый пункт и `grid-template-columns: repeat(5, …)`.

- `aroma-atelier-design`:
  - ICONOGRAPHY: у гостя добавляются `circle-user-round` (нижняя панель) и `heart` (карточка микса);
  - гостевой кит — пятый пункт панели и сердечко в `MixSheet`;
  - в readme убрать «Гость не регистрируется» (уже правится в PR #236).
