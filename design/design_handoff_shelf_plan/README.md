# Handoff: «В плане» от идеи до полки (#559)

Сейчас «В плане» на «Полке» — тупик: табак ставится в план из «Идей для закупки», дальше система о нём
молчит. Мокап замыкает цикл: идея → план → «К заказу» → приход → проба → держим или нет. Сделан по
скиллу `atelier-feature-design`, бриф и решения Р1–Р8 — в #559.

Статус: **согласован владельцем 2026-11-13.** Четыре вопроса из раздела «На решение владельцу» приняты
как показаны в мокапе.

## Как открыть

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Затем `http://localhost:8765/design/design_handoff_shelf_plan/mockups.html`.

- Доска: кадры по разделам, у каждого — срез (S1–S7) и `#shot=`.
- `mockups.html#shot=<id>` показывает один экран без доски: десктоп 1280×800, телефон 375×780.
- `screens/` содержит снимки всех кадров (`<id>.png`).

## Файлы

- `mockups.html` — оболочка «Мастера» из #518 и классы `.pl-*`.
- `board.jsx` — экраны на примитивах кита «Мастера» и доска.
- `data.js` — табаки в плане как на проде 13 ноября (Догма Лемон дропс, Bonche Caramel, Bonche Clover Club),
  счёт Каспий Опт 1207, миксы под план.

## Ответы клиента (2026-11-13)

1. Табак без счёта не приходит. «В наличие» из плана нужен для единообразия с «На полку» в «Каталоге».
2. Своего списка «хочу попробовать» у мастера нет: он смотрит новинки и сам делает аналитику. План и есть её итог.
3. Различать «хочу закупить» и «уже заказал» не нужно.
4. Держать новинку постоянно решает мастер.

## Решения владельца (2026-11-13, по мокапу)

1. **Счётчик «К заказу»** считает закончившиеся вместе с планом (8 = 4 + 4). Альтернатива — только закончившиеся.
2. **«В наличие» в «К заказу»** не показан: там собирают заказ, а не отмечают наличие. Действие есть на «Полке».
3. **Выделение старого плана** — дата цветом предупреждения, если в плане больше 30 дней. Порог условный.
4. **Подсказка после «Зашло»** (`card-trial-yes`) дублирует переключатель «Держим постоянно» ниже. Альтернатива —
   без подсказки, только переключатель.

## Реализовать

- Дата постановки в план: `createdAt` строки полки не годится (убранный табак, поставленный в план снова,
  сохраняет старую строку). Дата из аудита `add` или поле `plannedAt` — схема отдельным срезом на human review.
- «К заказу» отдаёт план отдельным списком; копирование — только названия.
- Статус микса «ждёт табак из плана» — разновидность «блокирован наличием», когда все недостающие табаки в плане.
  Гостю микс не виден, как и сейчас (инвариант 4); открывается с приходом.
- Метка «из плана» в строке счёта — по статусу полки сопоставленного табака.
- Табак, пришедший из плана, встаёт с `keepStocked = false`; подсказка «Держать постоянно» — после «Зашло».
- PRD §9.3 п. 2 и §9.4 п. 1 правятся в PR срезов S1 и S3.

## Что не меняется

Гостевой поток, «Идеи для закупки», загрузка и разбор счетов, аналоги, массовые действия (#517),
статусы «Есть», «Закончился», «Стоп».
