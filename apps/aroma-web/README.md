# Арома Ателье · Гость

Гостевой mobile-first frontend для продукта `Арома Ателье`.

## Назначение

Этот пакет отвечает за клиентский сценарий гостя:

1. `18+` gate;
2. ввод daily code;
3. подтверждение доступа;
4. знакомство;
5. онбординг;
6. рекомендации, витрина, каталог и модальная карточка микса;
7. фиксация `Выбрать` как явного guest CTA и события аналитики лаунжа;
8. кабинет гостя по желанию (#243): последний пункт нижней панели «Кабинет», вход
   через бота Telegram по ссылке, выход и удаление;
9. история и избранное (#244): выборы по дням, сердечко в карточке микса,
   повторный «Покурить» каталожного и собранного микса;
10. «Для вас» на Подборе (#245): у вошедшего гостя с тремя и больше выборами —
    раскладка по слотам «Новое в вашем вкусе», «Шаг в сторону», «Снова» с
    причиной у каждого микса и подсказкой «Давно на одном вкусе»; меньше трёх
    выборов — подбор по вкусам кабинета; «Подобрать под настроение» — онбординг
    на один визит;
11. «Рилсы» (#263): третий пункт нижней панели — миксы полноэкранной лентой
    со снапом «один жест — один рилс». Фон — сцена Remotion по вкусам микса
    (#262), «Покурить» — то же событие `smoke-cta`;
12. полоса рилсов над Подбором (#264): первые восемь миксов ленты кружками со
    статичным кадром сцены, кружок открывает «Рилсы» на своём миксе;
13. рилсы вошедшего гостя (#265): лента и полоса начинаются с «Для вас» со
    слотами, причинами и подсказкой Подбора; сердечко на рилсе.

Лента рилсов: сначала голова, затем остальной каталог без повторов
(`src/lib/reel-feed.ts`). Голова у гостя без входа — подбор по онбордингу;
у вошедшего — «Для вас» из уже загруженного `GET /guest/me/for-you`: в режиме
`personal` — слоты «Новое в вашем вкусе» → «Шаг в сторону» → «Снова» (с
подсказкой «Шаг в сторону» первым) с теми же фразами `for-you-copy.ts`, в
режиме `cold` — его выдача по вкусам кабинета. Своих запросов у ленты
вошедшего нет: из панели устаревший «Для вас» пересобирается тем же
запросом, который иначе сделал бы Подбор. Уже загруженные подбор и каталог не
запрашиваются заново. Играет только активный рилс: `ReelPlayer` — отдельный
чанк через `React.lazy`, пока он едет и у соседей — статичный `ReelStill`,
при `prefers-reduced-motion` — только `ReelStill`. На 404 от `smoke-cta`
микс помечается закончившимся до конца визита.

Полоса над Подбором собирается из тех же источников, что и лента, поэтому
номер кружка совпадает с номером рилса. Remotion на Подборе не рендерится:
после отрисовки чанк `ReelPlayer` подгружается в простое (`requestIdleCallback`,
в Safari — `setTimeout`), при `prefers-reduced-motion` — не подгружается.
Сердечко рилса — тот же `HeartButton` и то же избранное, что в карточке.

Кабинет не меняет анонимный путь. Токен гостя лежит в `localStorage`
(`aroma-guest-token`) и уходит в `Authorization` там, где его читает backend:
«Покурить», собранный микс, оценка и `/guest/me*`. На 401 токен стирается, а
гостевое событие повторяется анонимно. Логика без DOM — `src/lib/guest-session.ts`.

Избранное приходит один раз на старте у вошедшего гостя и дальше живёт
локально: сердечко шлёт только `PUT` или `DELETE`. История запрашивается при
каждом открытии кабинета. Карточка из строки кабинета собирается из самой
строки, без запросов. Группировка по дням, подписи строк и состояние
сердечка — `src/lib/cabinet.ts`.
Кнопка входа появляется, только если на backend задан
`ATELIER_GUEST_LOGIN_BOT_USERNAME`.

Подбор вошедшего гостя берёт выдачу из `GET /guest/me/for-you` вместо
`POST /guest/onboarding/recommendations`, второго запроса нет. После
«Покурить», оценки, сердечка, правки вкусов или «Намиксуй» выдача помечается
устаревшей и пересобирается при следующем заходе на Подбор. Правка вкусов
вошедшего — `PUT /guest/me/onboarding`, затем снова «Для вас». «Под
настроение» шлёт обычный `POST /guest/onboarding/recommendations` и не трогает
вкусы ни в кабинете, ни на устройстве; выдача живёт до «Вернуться к «Для вас»»
или перезагрузки. Фразы причин и решение «что делает „Показать подбор“» —
`src/lib/for-you-copy.ts`.

## Локальный запуск

```bash
cd apps/aroma-web
npm install
npm run dev
```

По умолчанию frontend слушает `5174`.

## Адрес API

API задаётся через `VITE_API_BASE_URL`; без переменной используется `http://localhost:3021`.

Файлы конфигурации, по возрастанию приоритета:

1. `.env.example` — образец, лежит в репозитории;
2. `.env.local` — локальное переопределение, **gitignored** и **перекрывает** `.env.example`.

`.env.local` удобен, когда гостя проверяют с телефона: туда прописывают IP машины
в текущей Wi-Fi-сети (`VITE_API_BASE_URL=http://192.168.1.x:3021`). Этот адрес
тихо протухает при смене сети, а файл не обновляется вместе с остальным конфигом —
поэтому при симптоме «вход не проходит, хотя backend поднят» первым делом смотреть
в `.env.local`, а не в `.env.example`.

Vite читает env только при старте: после правки `.env.local` dev-сервер нужно
перезапустить.

Запросы к API ограничены таймаутом в 8 секунд: недоступный хост даёт ошибку
«Не удалось связаться с сервером», а не зависший экран.

## UI-слой

В приложении поднят локальный foundation на `shadcn/ui` и `Tailwind CSS v4`.

Сейчас через этот слой проходят:

1. action-кнопки и tab-кнопки;
2. поля ввода и checkbox на экране доступа;
3. badges/chips в навигации, карточках и фильтрах;
4. card surfaces ключевых guest-screen;
5. модальная карточка микса через `Dialog`.

## Стадия

Текущая стадия: Phase 4 guest content flow + Aroma Polish + Yami Web Alignment.

Что уже приведено к новой подаче:

1. экран кода ведёт в знакомство с горизонтально свайпаемыми карточками;
2. онбординг работает на русских профилях вкуса и расширенном списке вкусов;
3. `Подбор`, `Витрина`, `Каталог` и экран рейла используют механику списков карточек, близкую к базовому `Yami Web`;
4. знакомство показывается один раз после ввода кода, занимает весь экран и не выводит основное меню;
5. intro-карточки рассказывают про предпочтения, витрину, каталог и завершаются приглашением перейти в `Арома Ателье`;
6. карточка микса открывается поверх текущего экрана, а событие `Выбрать` отправляется только по явному CTA внутри карточки;
7. зафиксированный микс закрепляется отдельной верхней панелью `Карточка для мастера` и не скроллится вместе с контентом;
8. витрина показывает редакторские подборки, подборки от мастеров и подборки `Больше всего выбирают`;
9. каталог уважает backend-фильтры по `profiles` и `flavors`, поэтому после онбординга и применения вкусовых фильтров выдача синхронизирована с guest API;
10. в мобильном каталоге кнопка `Найти` вынесена в верхний action-row и не прячется внизу формы.
11. визуальный слой подтянут к стилю `Арома Ателье`: бордовая палитра, тёплые янтарные акценты, serif-wordmark и более атмосферные поверхности карточек.
12. базовые UI-примитивы теперь централизованы в `src/components/ui`, а не размазаны только по монолитному `App.tsx`.
