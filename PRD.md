# PRD — Арома Ателье (Aroma Atelier)

## 1. Обзор продукта

Самостоятельный продукт **«Арома Ателье»** — сервис подбора кальянных миксов для
заведения. Состоит из трёх связанных контуров:

1. `Арома Ателье` — гостевой mobile web: весь путь без обязательной авторизации, личный кабинет — по желанию через вход в Telegram.
2. `Мастер` — staff web для кальянных мастеров и администратора.
3. `Telegram-бот Арома Ателье` — канал распространения недельного кода доступа для персонала.

Цель MVP: быстро доводить гостя от QR-кода до понятной карточки микса, которую он показывает кальянному мастеру, а персоналу дать простой и поддерживаемый контур управления наличием, миксами, рейлами и статистикой.

## 2. Цели продукта

### 2.1 Бизнес

* повысить конверсию из сканирования QR в нажатие `Покурить`;
* сократить время подбора микса гостю;
* держать рекомендации в актуальном состоянии за счёт учёта реального наличия табаков;
* дать заведению инструмент ежедневной операционной работы без ручного хаоса.

### 2.2 Пользовательские

#### Гость

* быстро понять, как работает сервис;
* выбрать, что покурить, без регистрации;
* постоянному гостю — вернуться к любимым миксам и получать подбор с учётом своих прошлых выборов;
* получить готовую карточку микса, которую можно показать мастеру;
* при желании оценить микс.

#### Кальянный мастер

* одним касанием отметить, что банка закончилась;
* принимать поставки по счёту поставщика без ручного ввода каждой строки;
* видеть расход табака, на сколько дней хватит и что пора заказать;
* добавлять новые табаки и миксы;
* собирать и редактировать рейлы;
* видеть, что чаще выбирают гости.

#### Администратор

* управлять всем каталогом и staff-доступом;
* контролировать недельный код доступа и статистику;
* иметь единый источник правды по каталогу и аналитике.

## 3. Роли и доступ

### 3.1 Aroma Atelier

Доступ без обязательной авторизации. Вход через Telegram — по желанию гостя и открывает личный кабинет (§8.9); без входа весь путь ниже работает как прежде.

Гость проходит:

1. QR-старт;
2. age gate `18+`;
3. ввод недельного кода, который ему сообщает мастер зала;
4. знакомство;
5. онбординг по вкусовым предпочтениям;
6. рекомендации / главная / каталог / «Намиксуй» / карточка микса;
7. действие `Покурить`;
8. оценка микса.

### 3.2 Master

Доступ только по логину и паролю.

Поддерживаются две учётные записи:

1. `admin` — полный доступ владельца системы;
2. `master` — staff-доступ для кальянных мастеров.

На MVP права можно реализовать двумя ролями:

1. `admin` — полный CRUD + управление staff + служебные настройки;
2. `staff` — работа с наличием, миксами, рейлами и просмотром дашбордов.

### 3.3 Telegram-бот

Бот доступен только персоналу заведения и выдаёт недельный код доступа. Для гостя бот — только провайдер входа в личный кабинет (Telegram Login): он не ведёт с гостем диалог и ничего ему не рассылает.

## 4. Ограничения и инварианты

1. Интерфейс полностью на русском языке.
2. Гостевой путь не требует авторизации: код, онбординг, рекомендации, каталог, «Намиксуй» и `Покурить` работают анонимно. Вход через Telegram — по желанию гостя и открывает личный кабинет (§8.9); недоступность Telegram не ломает анонимный путь.
3. Личный кабинет — история выборов, избранное и персональный подбор «Для вас» (§6.5). Сессий курения нет: история — журнал нажатий `Покурить`, без начала, конца и длительности.
4. Кабинет хранит минимум персональных данных: Telegram id, отметку согласия и вкусы из онбординга, без телефона. Гость может удалить кабинет — история и избранное удаляются, события для статистики остаются без связи с гостем. Кабинет действует в пределах одной точки; мастер кабинет гостя не видит; гостю ничего не рассылается.
5. Кнопка `Покурить` не создаёт пользовательскую smoking-session, а пишет аналитическое событие выбора микса; у вошедшего гостя событие попадает в его историю. Для микса, который гость собрал сам в «Намиксуй» (§8.8), пишется отдельное событие выбора гостевого микса; гостевой микс не попадает в каталог и statistical-рейлы, а вошедшему гостю сохраняется в историю и может быть добавлен в избранное.
6. Механика оценок сохраняется.
7. Перед доступом к основному функционалу обязателен экран подтверждения `18+`.
8. В рекомендациях и каталоге должны учитываться только табаки, доступные по текущему наличию, если сценарий явно не допускает показ недоступных позиций. Табак в наличии, если на полке есть его банка в запасе или в работе, на нём не стоит «стоп для гостей» и он не в архиве (§9.3).
9. Для каталога табаков использовать разделение: `flavorProfiles` — категории, `flavors` — вкусы, `flavorTags` — только мета-теги.
10. Визуальная база продукта — единая дизайн-система **Film Noir** (см. §12): тёмный
    дымчатый уголь, тёплый туманно-серый текст, единственный глубокий акцент-бордо
    `#8E2F3C`. Применяется в обоих веб-приложениях как source of truth.

## 5. Сущности домена

### 5.1 Каталог

* `Manufacturer`
* `Tobacco`
* `Mix`
* `MixComponent`

### 5.2 Операционный контур

* `ShelfItem` — табак на полке точки: фасовка по умолчанию, «держим постоянно», «стоп для гостей», статус (держим / в плане / не держим). Каталог (`Tobacco`) о наличии не знает
* `Pack` — банка (пачка 25 г — тоже банка): вес, цена, даты прихода, вскрытия, окончания или списания
* `PackMark` — отметка остатка открытой банки (¾ ½ ⅓ ¼) в момент времени
* `ShelfSettings` — граммовка чаши и срок поставки
* `Supplier`, `SupplierItem` — поставщик и память сопоставлений «строка его счёта → табак каталога»
* `Delivery`, `DeliveryLine` — поставка по счёту поставщика: номер, даты счёта и прихода, строки с ценой, файл счёта
* `Rail`
* `RailItem`
* `DailyAccessCode`
* `StaffUser`

### 5.3 Аналитика

* `GuestAccessAttempt`
* `GuestOnboardingResult`
* `SmokeIntentEvent` — нажатие на `Покурить`; у вошедшего гостя — со ссылкой на `GuestAccount` и снимком микса, чтобы история пережила удаление микса
* `CustomMixSmokeEvent` — нажатие на `Покурить` на миксе, собранном гостем в «Намиксуй»: снимок состава и долей; у вошедшего гостя — со ссылкой на `GuestAccount`
* `MixRating` — у вошедшего гостя одна оценка на микс, повторная оценка её заменяет

### 5.4 Личный кабинет

* `GuestAccount` — Telegram id, отметка согласия, вкусы из онбординга
* `GuestFavorite` — избранный микс гостя: каталожный или собранный в «Намиксуй»

## 6. Рекомендательная логика

### 6.1 Основа MVP

Персональная рекомендация формируется на основе:

1. ответов текущего гостя в онбординге;
2. состава микса;
3. актуального наличия табаков на кухне.

### 6.2 Правила MVP

1. Если хотя бы один компонент микса отсутствует в наличии, такой микс не должен попадать в основную гостевую рекомендацию.
2. Онбординг должен быть коротким и приводить к полезной первой выдаче за 1-2 минуты.
3. Рекомендация должна быть объяснимой на уровне продукта: вкусовые профили, вкусы, крепость, настроение.
4. При отсутствии сильного совпадения пользователь должен быстро перейти к рейлам или каталогу.

### 6.3 Без ML на старте

На MVP не требуется ML-персонализация. Достаточно rule-based ранжирования, которое использует:

* совпадение по `flavorProfiles`;
* совпадение по `flavors`;
* штраф за конфликтующие ответы;
* бонус за статистическую популярность;
* бонус/сортировку по оценкам.

ML допустим только как следующий этап после накопления стабильных событий.

### 6.4 «Намиксуй»

Гость собирает микс сам из табаков в наличии (§8.8). Правила:

1. В колоде только табаки в наличии и не в архиве; перед записью события наличие перепроверяется.
2. Фильтры первой колоды заранее выставлены по профилям из онбординга; гость может выбрать несколько полок или снять фильтры.
3. Колода штриха ограничена табаками с мета-тегом `охлаждающий` и профилями `minty`, `spicy`.
4. Гармония чаши — rule-based: сродство `flavorProfiles`, взвешенное долями, и штрафы ремесла (холодка больше 20%, основа меньше 35%, штрих больше 25%). Сродство пары профилей — во сколько раз мастер сводит их в миксах каталога чаще, чем они сошлись бы у табаков, взятых с полки наугад: «Классику» получает сочетание, которое мастер выбирает чаще случайного, а не просто популярные профили. Вердикт информирует и не запрещает выбор.
5. Похожий микс подбирается только из миксов гостевого каталога в наличии.

### 6.5 «Для вас»

Персональный подбор для вошедшего гостя. Строится rule-based (§6.3) по онбордингу, истории `Покурить` (собранные миксы — по профилям их табаков), оценкам и избранному; правило наличия §6.2 сохраняется. Пока у гостя меньше трёх выборов, подбор идёт по сохранённому онбордингу.

Любимое доступно в один тап из истории и избранного, поэтому «Для вас» работает на открытие нового и не запирает гостя в пузыре одного вкуса:

1. Не больше одной карточки из уже выбранных гостем миксов.
2. Минимум одна карточка «Шаг в сторону» — микс с ведущим профилем, которого нет в истории гостя, но который мастера сводят с его любимыми профилями чаще случайного (сродство из §6.4).
3. Один микс засчитывается во вкус гостя не больше трёх раз; выборы старше 60 дней весят вдвое меньше.
4. Не больше двух карточек с одним ведущим профилем.
5. Если четыре из пяти последних выборов — один микс или один ведущий профиль, над подбором появляется мягкая подсказка попробовать «Шаг в сторону». Подсказка информирует и не запрещает выбор.

Каждая карточка объясняет, почему она в подборе. Числа в правилах — стартовые и уточняются по итогам пилота.

## 7. Рейлы

Рейл обязан иметь `type`.

Типы рейлов:

1. `statistical` — статистические рейлы.
2. `prepared` — предзаготовленные рейлы.
3. `curated` — рейлы, сформированные кальянными мастерами.

### 7.1 Обязательные statistical-рейлы MVP

1. `Топ по кнопке "Покурить"`
2. `Топ по оценкам`

### 7.2 Правила показа

1. На `Главной` Aroma Atelier пользователь видит рейлы, если рекомендации не подошли или он хочет продолжить выбор.
2. Предзаготовленные и curated-рейлы управляются через `Мастер`.
3. Statistical-рейлы пересчитываются автоматически по аналитическим событиям.
4. Statistical-рейлы считаются только по миксам каталога; гостевые миксы из «Намиксуй» в них не попадают.

## 8. Экранная модель Aroma Atelier

### 8.1 `18+`

Экран подтверждения возраста перед любым дальнейшим действием.

### 8.2 Ввод кода

Пользователь вводит ежедневный код доступа, полученный от мастера зала.

### 8.3 Знакомство

Набор карточек, которые объясняют сценарий использования сервиса.

### 8.4 Онбординг

Короткий сценарий выбора предпочтений:

* профили вкуса;
* конкретные вкусы;
* при необходимости дополнительные фильтры, если они помогают быстрее получить релевантную выдачу.

Результат онбординга: список карточек рекомендованных миксов.

Вошедший гость онбординг повторно не проходит: на знакомстве и онбординге есть вход «Уже были у нас?», после него гость сразу попадает на подбор с «Для вас». Вкусы меняются из кабинета.

### 8.5 Главная

Список рейлов, доступных гостю после рекомендаций.

### 8.6 Каталог

Самостоятельный выбор микса с поиском и фильтрами.

### 8.7 Карточка микса

Карточка обязана содержать:

1. название микса;
2. состав и пропорции;
3. вкусовые профили;
4. описание;
5. CTA `Покурить`;
6. возможность поставить оценку.

После нажатия `Покурить` открывается чистая карточка-подтверждение, удобная для показа кальянному мастеру.

### 8.8 «Намиксуй»

Гость сам собирает микс за три хода. Вход — пункт «Миксер» в нижней панели гостя и карточки-приглашения на `Главной` и в конце рекомендаций. Миксер открывается на весь экран без панели, «Назад» возвращает на экран, откуда гость пришёл.

1. Ходы: основа (40–70%), акцент (20–40%), штрих (5–15%, можно пропустить).
2. На каждом ходе — бесконечная колода карт табаков: свайп вправо кладёт табак в чашу и открывает следующий ход, свайп влево показывает следующую карту. Есть кнопки для тех же действий, возврат последней пропущенной карты и «Доверюсь мастеру» — дособрать оставшиеся ходы автоматически.
3. Карта показывает профиль, бренд, название, вкусы и мета-тег холодка; на акценте и штрихе — совпадение с уже собранной чашей.
4. Раскрытие: имя микса (гость может переименовать), доли с шагом 5%, характер, вердикт гармонии, похожий микс из каталога.
5. `Покурить` открывает ту же карточку для мастера с составом и долями и пометкой «Собран гостем».

### 8.9 Личный кабинет

Пункт «Кабинет» в нижней панели гостя. Без входа — объяснение, зачем входить, и вход через Telegram с согласием на обработку данных; после входа гость возвращается на экран, откуда пришёл, а вкусы из онбординга текущего прохождения переходят в кабинет.

1. История: каждое нажатие `Покурить` по датам — микс, оценка гостя, «Покурить снова». Собранные миксы — с пометкой «Собран вами».
2. Избранное: сердечко на карточке микса и на собранном миксе; список в кабинете. Микс без наличия остаётся в списке с пометкой и без `Покурить`; удалённый мастером — с пометкой «больше не готовим».
3. «Изменить вкусы» — повторный онбординг.
4. Выход и удаление кабинета.

## 9. Экранная модель Master

### 9.1 Авторизация

Логин/пароль для `admin` и `master`.

### 9.2 Дашборд по сессиям курения

На MVP трактуется как дашборд по аналитическим событиям выбора миксов, а не по реальным пользовательским аккаунтам.

Базовые метрики:

* нажатия `Покурить` по дням;
* топ миксов;
* top / anti-top профили вкусов;
* конверсия из онбординга в `Покурить`, если событие онбординга сохраняется.

### 9.3 Инвентаризация

Каталог (что бывает) и полка (что держит точка) — разные экраны. Согласованный мокап и
формулы — `design/design_handoff_inventory/`.

1. **Полка.** Табаки точки с банками: в запасе и в работе, остаток, расход, «хватит до»,
   статус (есть / последняя банка / заканчивается / закончился / стоп / в плане). Поиск
   и фильтры — мгновенные.
2. **Жизненный цикл банки:** в запасе → в работе → пустая (или списана). Вскрытие
   определяется автоматически: в работу идёт старейшая банка из запаса, когда закончилась
   предыдущая. Мастер отмечает только «Закончилась» (с отменой); остаток ¾ ½ ⅓ ¼ — по желанию.
3. **Стоп для гостей** — табак на полке есть, но гостю не предлагается.
4. **Поставки.** PDF счёта поставщика разбирается в строки, строки сопоставляются
   с каталогом (подтверждённые сопоставления запоминаются за поставщиком); мастер отмечает,
   что пришло, и принимает поставку — банки появляются на полке. Поддерживаются форматы
   счетов текущих поставщиков; скан без текста — ручной ввод строк.
5. **Каталог.** Карточки htreviews и свои, поиск, создание карточки. «Идеи для закупки» —
   табаки не с полки по рейтингу, оценкам и просмотрам htreviews со ссылкой на сайт.

### 9.4 Расход, прогноз и дашборд по инвентаризации

1. Расход табака (г/день) считается по датам вскрытия, отметок и окончания банок за последние
   60 дней; пока данных нет — оценка по бренду.
2. «Хватит до» — остаток открытой банки и запас, делённые на расход.
3. «К заказу» — табаки, которые держим постоянно или запланировали, если закончатся
   в пределах срока поставки; количество — расход на 21 день; текст заказа для поставщика.
4. Дашборд: прогноз расхода на сегодня (г и чаши), что заканчивается, траты по поставщикам,
   себестоимость чаши, расход по неделям.

Вне scope: автосписание по `Покурить`, несколько точек, бухгалтерия (оплаты, НДС, 1С),
LLM-разбор и OCR счетов, отметки из Telegram-бота.

### 9.5 Менеджер миксов

CRUD для миксов и их компонентов.

### 9.6 Менеджер рейлов

CRUD для рейлов всех типов и управление наполнением.

## 10. Telegram-бот

MVP-функции:

1. ежедневная генерация или публикация кода;
2. отправка кода в staff-чат или ограниченному списку пользователей;
3. ручной запрос текущего кода командой;
4. журнал последнего активного кода.

## 12. Дизайн-система Film Noir

Единая дизайн-система обоих веб-приложений (`Арома Ателье` и `Мастер`) — **Film Noir**:
тёмная, спокойная, кинематографичная. Тёплый туманно-серый текст на дымчатом угольном
фоне, единственный глубокий акцент-бордо (до 2026-09-24 — оксблад `#B04A3E`, заменён
по решению владельца бренда: на экране читался оранжевым). Оба приложения
резолвят **идентичные** значения токенов — это source of truth, дублировать палитры
запрещено.

| Группа | Токен | Значение |
|---|---|---|
| Поверхности | `--bg-base` / `--bg-raised` / `--bg-elevated` / `--bg-overlay` | `#141417` / `#1C1C21` / `#232329` / `#2B2B32` |
| Текст | `--text-primary` / `--text-secondary` / `--text-muted` / `--text-faint` | `#E8E6E0` / `#B6B4AE` / `#8F8D87` / `#6A6863` |
| Акцент (единственный) | `--accent` / `--accent-hover` / `--accent-deep` / `--accent-fg` | `#8E2F3C` / `#A33B48` / `#5C1C26` / `#F4EFEA` (текст на акценте) |
| Границы | `--border-subtle` / `--border-default` / `--border-strong` | тёплый серый с альфой 0.16 / 0.26 / 0.40 |
| Семантика | `--success` / `--warning` / `--danger` / `--info` | `#6E9A6A` / `#C2A24E` / `#CF4F44` / `#5E7E96` (тот же приглушённый регистр) |

Правила: акцент один (бордо) — не вводить второй «фирменный» цвет; сплошная заливка
акцентом — только у главного CTA, активная навигация «тихая» (графит + черта акцента);
текст и иконки акцентом не набираются: надзаголовки — `--text-muted`, активные иконки,
чипы и рейтинг — кремовые, ошибки — `--danger`; бордо остаётся метками (черта, точка,
рамка) и заливкой CTA, без отдельного золота; категорийные цвета
вкусовых профилей (`--profile-*` в гостевом контуре) — отдельный слой данных, не часть
бренд-палитры. Радиусы/шрифты/spacing/тени — общая шкала, не зависят от перекраса.

## 13. UI/UX-инварианты

1. Mobile-first для `Арома Ателье`.
2. Быстрый сценарий выбора без длинных обязательных форм.
3. Явные CTA и минимальное число шагов до первой рекомендации.
4. Визуальное направление — единая дизайн-система Film Noir (§12): тёмные дымчатые
   поверхности, единственный акцент-бордо, премиальный кинематографичный character.
5. Интерфейс мастера допускает более утилитарный стиль, но должен оставаться в общей палитре.

## 14. Нефункциональные требования

1. Все ключевые бизнес-правила тестируемы на уровне backend/domain.
2. Гостевой код должен иметь срок действия и возможность ежедневной ротации.
3. Любое изменение наличия должно отражаться в рекомендациях без ручной синхронизации данных между сервисами.
4. Система должна корректно работать без ML; гостевой путь — без входа гостя и при недоступности Telegram.
